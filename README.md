# Запись на консультацию к куратору (прототип)

Три роли, у каждой своя ссылка:

| Роль | Адрес | Что делает |
|---|---|---|
| **Ученик** | `/c/<код куратора>` или `/` + ввод кода | Видит **только своего** куратора и его свободные слоты, записывается, может отменить запись по коду отмены |
| **Куратор** | `/curator/<секретный токен>` | Выкладывает слоты на неделю (генератор «Пн–Пт с 16 до 19 по 45 мин» или копирование прошлой недели), видит записавшихся, отмечает «пришёл / не пришёл», отменяет запись |
| **Репетитор** | `/admin` (пароль) | Статистика по кураторам и неделям, выгрузка CSV, добавление и отключение кураторов, выдача ссылок |

**Изоляция кураторов.** Ученик попадает к куратору только по его коду (6 случайных символов). API отдаёт имя одного куратора и его свободные будущие слоты. Список кураторов и чужие записи ученику недоступны.

## Запуск

```bash
node server.js          # Node 18+, без зависимостей
# или
PORT=8080 ADMIN_PASSWORD=секрет node server.js
```

При первом запуске создаются два демо-куратора со слотами и записями. Все ссылки выводятся в консоль. Данные хранятся в `data/db.json`: удалите файл, чтобы начать с чистого листа.

## Статистика для репетитора

- выложено слотов, записей, загрузка (%);
- проведено, неявки, процент явки;
- отмены (учеником или куратором);
- «не отмечено»: прошедшие консультации без итога, чтобы видеть, кто из кураторов не ведёт учёт;
- число уникальных учеников;
- график по неделям, фильтр по периоду, CSV для Excel.

## Ограничения прототипа

- Хранилище: JSON-файл в одном процессе. Для продакшена нужна БД (SQLite/Postgres).
- Время хранится «как есть», без часовых поясов.
- Нет уведомлений: ни ученику, ни куратору ничего не отправляется.
